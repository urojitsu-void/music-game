# 音ゲー自動譜面・動画合成システム設計

## 目的

MP3、LRC、ジャケット画像、または既存のMP4/MOVを入力し、自動生成した音ゲー譜面を映像へ重ねた完成MP4を生成する。次段階では、動画出力と同じ見た目のブラウザ版音ゲーを提供する。

実装順は次のとおりとする。

1. 自動譜面とオートプレイ動画の生成・合成
2. 同じ譜面と描画処理を利用するブラウザ版ゲーム

## 今回の対象範囲

初期実装では次を提供する。

- Node.js CLI
- CLIを呼ぶだけの薄いmacOS用 `.command`
- 既存のFFT譜面生成処理を基にした自動譜面JSON生成
- 既存の `spectrum_video.command` のFFmpeg処理を再利用した背景MP4生成
- ゲーム部分だけを描画したアルファ付きProRes 4444 MOV生成
- 背景MP4と透明譜面MOVを合成したH.264 MP4生成
- 曲単位のビルドキャッシュ
- 動画出力とブラウザ版で共有できるCanvas描画モジュール
- 最初の素材 `HERE × HEAR.mp3/.lrc/.png` を使う動作確認

ブラウザで実際に遊ぶ機能は次段階で実装する。ただし、動画用描画をプレイ画面でも再利用できる境界を初期段階から用意する。

## 入力と成果物

素材は同じベース名で関連付ける。リポジトリには動作確認用として1曲分だけを `example/` 配下へ残す。

```text
example/HERE × HEAR/
├── HERE × HEAR.mp3
├── HERE × HEAR.lrc
└── HERE × HEAR.png
```

MP4/MOVが入力された場合は、その映像と内蔵音声を背景・譜面解析元として使う。MP3入力時は、MP3、LRC、ジャケットから既存FFmpeg処理で背景動画を生成する。

入力規則は次のとおりとする。

- MP3モードでは `.mp3`、同じベース名の `.lrc`、同じベース名の `.png`、`.jpg`、`.jpeg` のいずれか1枚を必須とする。
- 画像候補が複数ある場合は曖昧な入力として停止し、明示オプション `--cover` を要求する。
- LRCまたは画像が見つからない場合は、探索したパスを示して工程開始前に停止する。
- 動画モードでは `.mp4` または `.mov` を必須とし、音声トラックを内蔵している必要がある。外部LRCと画像は使用しない。
- 拡張子比較は大文字小文字を区別しない。
- 明示した入力パスを基準とし、別ディレクトリの同名素材は探索しない。

成果物は曲ごとのディレクトリへ保存する。

```text
output/HERE × HEAR/
├── background.mp4
├── chart.json
├── gameplay-alpha.mov
├── final.mp4
└── build-manifest.json
```

`output/` 以下は生成物であり、リポジトリの `.gitignore` へ追加する。サンプルとしてGit管理するのは `example/HERE × HEAR/` の入力素材1曲分だけとし、生成済みの背景動画、透明動画、完成動画は含めない。

- `background.mp4`: 歌詞、ジャケット、音声スペクトラムを含む事前生成動画
- `chart.json`: 自動生成譜面
- `gameplay-alpha.mov`: ゲーム部分だけを含むProRes 4444透明動画
- `final.mp4`: 背景とゲーム部分を合成した完成動画
- `build-manifest.json`: キャッシュ判定に使う入力ハッシュ、設定、処理バージョン

## システム構成

### CLIオーケストレーター

CLIは入力解決、各工程の実行順、キャッシュ判定、エラー表示を担当する。個別工程の音声解析や描画ロジックは持たない。

想定コマンドは次の形式とする。

```bash
node src/cli.mjs build <audio-or-video-path>
```

リポジトリ同梱サンプルの実行例は次のとおりとする。

```bash
node src/cli.mjs build "example/HERE × HEAR/HERE × HEAR.mp3"
```

主なオプションは難易度、出力先、レーン配置、強制再生成とする。`.command` はこのCLIを起動するだけにし、処理ロジックを重複させない。

設定の優先順位は `CLIオプション > 入力ディレクトリの music-game.config.json > 組み込み既定値` とする。初期版の設定ファイルは任意であり、未知のキーと型違いは黙って無視せずエラーにする。実行時に解決した全設定をマニフェストへ保存する。

初期版の主な既定値は、難易度 `normal`、4レーン、seed `12345`、ノーツ移動時間2.0秒、出力ルート `./output`、MP3モードの背景1280×720・30fpsとする。CLIには `--difficulty`、`--seed`、`--out-dir`、`--cover`、レーン領域の `--game-x`、`--game-y`、`--game-width`、`--game-height` と、各強制再生成オプションを用意する。初期版ではレーン数を変更するCLIオプションは公開しない。

### 背景動画生成

既存の `/Users/teradonburi/Desktop/spectrum_video.command` にあるFFmpegフィルター構成をNode.jsから非対話で呼べるモジュールへ移す。ジャケット、スペクトラム、LRC由来字幕の見た目は既存処理を維持する。

MP3モードでは、参照実装と同じ1280×720、30fpsの背景MP4を生成する。動画モードでも成果物契約を統一するため必ず `background.mp4` を生成する。入力動画の解像度とフレームレートを維持し、MP4コンテナで安全にコピーできるH.264/AACストリームは再多重化し、それ以外はH.264/AACへ変換する。回転メタデータは表示方向へ適用する。

透明動画と最終動画の解像度・フレームレートは、FFprobeで得た `background.mp4` の値に合わせる。したがってMP3モードは1280×720・30fps、動画モードは入力動画相当となる。最終MP4も同じ寸法とfpsを維持する。

参照実装から維持・変更する範囲は次のとおりとする。

| 項目 | 方針 |
| --- | --- |
| ジャケットの拡大・中央クロップ | 維持 |
| 画面下部の7色 `showfreqs` | 維持 |
| LRCからSRTへの変換 | 維持し、Node.jsモジュールへ移植 |
| 字幕スタイル | 維持 |
| 1280×720・30fps | MP3モードで維持 |
| AppleScriptのファイル選択 | CLI入力へ置換 |
| FFmpeg実行とエラー通知 | Node.jsの子プロセスとログへ置換 |

### 譜面生成

既存の `/Users/teradonburi/Desktop/mp3-chart-generator/make-chart.mjs` を、CLI、解析、テンポ推定、レベルデザイン、JSON出力へ分割して取り込む。

初期版は4レーンを既定値とし、タップノーツを中心に生成する。同時押しは専用型を作らず、同じ時刻に異なるレーンのノーツを複数置く。譜面形式は将来のロングとフリックを追加できる構造にするが、確度の低い自動生成を初期版へ無理に含めない。

`chart.json` の初期スキーマは次のとおりとする。

```json
{
  "formatVersion": 1,
  "audio": "HERE × HEAR.mp3",
  "duration": 210.123,
  "bpm": 170,
  "beatOffset": 0.08,
  "beatsPerBar": 4,
  "difficulty": "normal",
  "lanes": 4,
  "seed": 12345,
  "notes": [
    { "time": 1.412, "lane": 0, "type": "tap" }
  ],
  "statistics": {}
}
```

- 時刻と長さの単位は秒とし、背景音声の開始を0秒とする。
- `duration` は0より大きい有限数、`bpm` は40〜250、`beatOffset` は0以上、`beatsPerBar` は初期版では4とする。
- `difficulty` は `easy`、`normal`、`hard`、`lanes` は初期版では4とする。
- `seed` の既定値は12345で、同じ入力・設定・実装バージョンでは同じ譜面を生成する。
- `notes` は `time`、次に `lane` の昇順とする。`time` は0以上かつ `duration` 以下、`lane` は0〜3、初期版の `type` は `tap` のみとする。
- 同時押しは同じ `time` と異なる `lane` を持つ複数要素で表す。同一時刻・同一レーンの重複は禁止する。
- `statistics` は診断情報であり、描画側は内容に依存しない。

### 共通ゲーム描画

描画は時間を外部から渡す決定論的なCanvasモジュールとする。

```text
renderFrame(canvas, chart, timeSeconds, layout, theme, playState)
```

動画生成では時刻をフレーム番号から算出し、ブラウザ版では音声・背景動画の現在時刻を渡す。同じ関数を使うことで、レーン、ノーツ、判定位置、発光、コンボ表示の見た目を揃える。

初期テーマは次のとおりとする。

- 上側が狭く、判定側へ広がる4本の遠近レーン
- レーン背景は塗らず、薄い境界線だけを常時表示
- ノーツは円形
- ノーツ種別を色で区別できるテーマ構造
- 入力映像上でも埋もれない内側ハイライトと暗い外周
- 判定線は画面最下部へ固定せず、位置・幅・高さを設定可能
- ノーツは上から下へ移動し、手前ほどわずかに拡大

プレイ操作はまだ確定しない。将来はPCのキーボードとマウスの併用、およびスマートフォンのマルチタッチを検討する。描画と譜面形式を特定操作へ依存させない。

描画契約は次のとおりとする。

- `layout`: 出力ピクセル単位の `width`、`height` と、0〜1の正規化座標で表すレーン上端中央、上端幅、判定線中央、判定線幅、判定線Y座標を持つ。既定値はテーマ内に定義し、CLIでレーン全体のX、Y、幅、高さを上書きできる。
- `theme`: レーン線、タップノーツ、判定ターゲット、発光、文字の色・太さ・半径を持つ。初期版は組み込みテーマ1種とする。
- `playState`: フェーズ1では `{ mode: "autoplay" }` のみを使う。コンボやヒット状態は譜面と `timeSeconds` から純粋に導出し、フレーム間の隠れた可変状態を持たない。
- ノーツの既定移動時間は2.0秒とする。`note.time - 2.0` でレーン上端に現れ、`note.time` に判定ターゲットへ到達する。
- 到達前は遠近レーン上を線形の時間比で移動し、半径は上端から判定側へ線形補間する。
- 到達時に120msのヒット発光を表示し、その後ノーツ本体を消す。
- オートプレイのコンボは `time <= timeSeconds` のノーツ数とし、同時押しの各ノーツを1カウントする。すべてPerfect扱いとする。
- 描画対象は出現時刻からヒット演出終了までのノーツだけとし、同じ引数なら常に同じピクセル結果を返す。

### 透明動画生成

ヘッドレスChromiumで共通Canvas描画を決定論的に進め、アルファ付きPNGフレームをディスクへ大量保存せずFFmpegへストリームする。FFmpegはフレームをProRes 4444へエンコードし、`gameplay-alpha.mov` を生成する。

動画出力の解像度とfpsは背景動画に合わせる。レーン領域の位置と寸法は設定で変更できる。PNGはRGBAのままFFmpegへ渡し、ProRes 4444のアルファ形式を明示してエンコードする。

### 最終合成

FFmpegで `background.mp4` の映像へ `gameplay-alpha.mov` をアルファ合成する。音声は背景動画側を採用し、映像時間は背景に合わせる。完成動画はH.264/AACの `final.mp4` とする。

## キャッシュ

各工程は、入力内容と設定からキャッシュキーを作る。ファイルの更新時刻だけには依存せず、SHA-256と処理バージョンを使う。

- 背景キー: 音源、LRC、ジャケットまたは入力映像、背景FFmpeg設定、背景処理バージョン
- 譜面キー: 解析対象音声、難易度、レーン数、BPM関連設定、譜面生成バージョン
- 透明動画キー: 譜面JSON、レイアウト、テーマ、解像度、fps、描画処理バージョン
- 最終合成キー: 背景動画、透明動画、エンコード設定、合成処理バージョン

変更された工程と、その成果物に依存する後続工程だけを再実行する。次の強制オプションを用意する。

```text
--force-background
--force-chart
--force-overlay
--force-final
--force-all
```

マニフェストは工程ごとのキー、成果物ハッシュ、成功時刻を持つ。各工程の成果物を一時ファイルから確定名へ置換した直後に、その工程の項目だけを原子的に更新する。後続工程が失敗しても、成功済み工程は次回再利用できる。成果物が存在しない、成果物ハッシュが違う、キーが違う場合は、その工程と依存する後続工程を再実行する。失敗した途中成果物を有効なキャッシュとして扱わない。

## エラー処理

- Node.js 20以上を必須とする。
- 起動時にNode.js、FFmpeg、FFprobe、プロジェクト依存関係として導入するPlaywright Chromiumを検査する。Chromiumが未導入の場合は `npx playwright install chromium` を案内して停止する。
- FFmpegのフィルター一覧に `subtitles` があることを背景生成前に確認し、ない場合はlibass対応FFmpegが必要であることを示す。
- 入力素材の不足、読めないLRC、音声トラックのない動画を工程開始前に報告する。
- 子プロセスには引数配列を渡し、ファイル名の空白や `×` などを安全に扱う。
- FFmpeg失敗時は実行工程と要点を表示し、詳細ログを曲の出力ディレクトリへ保存する。
- 一時出力へ書き出してから最終ファイル名へ置換し、中断時に既存の正常成果物を壊さない。
- キャッシュ不整合時は該当工程だけを自動再生成する。

## テスト方針

### 単体テスト

- LRC解析とSRT変換
- 入力素材の関連付け
- キャッシュキーと無効化規則
- 譜面JSONの検証
- 遠近レーン上の時刻から座標・大きさへの変換
- 同時刻の複数ノーツを独立ノーツとして扱うこと

### 結合テスト

- 短い合成音源から背景、譜面、透明MOV、完成MP4を生成
- FFprobeで解像度、fps、コーデック、音声、長さを検証
- 透明MOVにアルファチャンネルがあることを検証
- 2回目のビルドで全工程がキャッシュヒットすることを検証
- LRCだけを変更した場合、背景と最終合成だけが再実行されることを検証
- 譜面設定だけを変更した場合、譜面、透明動画、最終合成だけが再実行されることを検証

### 視覚確認

`example/HERE × HEAR/` の素材を使い、ノーツの同期、歌詞との重なり、レーンの視認性、遠近感、発光、最終合成のアルファ境界を確認する。ブラウザ版追加時には、同じ時刻の動画フレームとプレイ画面を画像比較する。
